# 手机 Web 与主屏幕 Web App

2026-10-01 首版：同一 Vue 前端与 Web API，Android 客户端不改动。

## 日常使用

- 窄于 900px 使用底部媒体库/发现/收藏/更多导航；桌面保留侧栏。玻璃胶囊中的选中滑块可横向拖动，松手切换到最近栏目；点按和键盘链接操作仍可直接切换。拖动中不加载新页面，取消手势不切换；系统手势区域保留。
- 媒体分类一排居中；空间不足时从完整的首项开始横向滚动，不截掉第一项。
- 媒体库按类型筛选，筛选和排序从底部弹出。搜索、标签、排序、来源和页码写入 URL；同一会话返回列表恢复滚动位置。
- 手机漫画默认卷轴；手机阅读模式和目录收起状态与桌面分别保存。单页图片支持滑动切换、双指缩放和放大后平移。
- 音频在全局组件播放。收起继续播放，关闭明确停止；开始播放视频会暂停音频。当前音轨及播放位置保存在本机浏览器，尚不跨设备同步。
- 下载继续由服务器执行；更多→下载任务汇总 WNACG/ASMR 和 Pawchive。查看详情与重试返回相应来源。

## iPhone 安装

Safari 打开 `http://192.168.0.101:8011`→分享→添加到主屏幕→保持“作为 Web App 打开”（如有此选项）。无需修改 hosts、开发者模式、签名或 App Store。手机需要能访问服务器所在局域网。访问地址改变后需重新登录，并从新地址重新添加主屏幕入口。

manifest 使用 standalone，支持横屏视频，viewport-fit=cover 与安全区 CSS 配合。180/192/512px 图标与 maskable 图标由 `frontend/scripts/generate-app-icons.py` 生成，依赖已有 Pillow；几何图形与 HE 字标一致。

## 更新、连接与边界

构建生成 `version.json` 与前端内嵌的相同 buildId；网页在恢复前台/联网及可见时每分钟检查。发现新版提示用户刷新，不自动重载。index 与 version.json 不缓存。

本版不注册 Service Worker，不缓存鉴权 API、视频/音频 Range 或媒体原文件。网络断开时显示状态，仍需要连接服务器才能继续请求内容。未来离线缓存和推送需要可信 HTTPS；当前内网 HTTP 入口可先使用移动网页和主屏幕入口。前端直接发布到宿主机局域网 IP 的 8011 端口，不再依赖 Nginx Proxy Manager 网络；仅停用 `hemanager.local` 这条代理，其他站点不变。后端及 Android 使用的 8010 端口不变。

Docker Compose 支持通过 `HE_FRONTEND_BIND_IP`（默认 `192.168.0.101`）和 `HE_FRONTEND_PORT`（默认 `8011`）更换局域网入口。容器内部 nginx 继续提供静态页面并转发同源 API/媒体请求。外层代理停用前已备份 NPM 数据库和原配置至其 `/data/backups/hemanager-direct-2026-09-30T17-16-28-996Z`。

iOS 锁屏播放、后台连续切轨、系统媒体控件、来电中断恢复及主屏幕启动需要真实 iPhone 验收；桌面浏览器触控模拟不代表这些系统行为已验证。

## 主屏幕底部空白兼容修复

2026-10-01：用户在 iPhone Air / iOS 27.0 的主屏幕模式反馈底部大段空白。普通浏览器继续使用动态视口 `100dvh`；主屏幕模式通过 display-mode 或 navigator.standalone 识别，使用完整 `100vh`。底部导航进入应用纵向 flex 布局，不再依靠系统 fixed 底边，也不重复预留整栏高度；手势安全区仍保留在导航栏内部。

visualViewport 的小幅安全区差异不用于缩短页面。仅在编辑输入且可见区域明显缩小时响应键盘；键盘关闭后恢复全高和底栏。媒体详情、音频与 Pawchive 查看器共用应用高度。登录页面在键盘上方可滚动到提交按钮。页面重新进入前台时重新检查视口，无需重新添加图标。

相关 WebKit 报告：[主屏幕高度计算偏小 #254868](https://bugs.webkit.org/show_bug.cgi?id=254868)、[iOS 27 的系统视口回归 #301994](https://bugs.webkit.org/show_bug.cgi?id=301994)。这些是兼容依据，不代表已确认用户设备的具体根因；系统绘制的不可达区域不能靠硬编码屏幕高度覆盖。

修复后生产构建与 38 项测试通过。Chromium 模拟主屏幕模式覆盖 320×568、390×844、420×912、844×390：底栏与页面底部相接，无根页面额外滚动区，键盘关闭后恢复；登录按钮可达，普通浏览器及两种模式的播放器回归通过。真实 iPhone Air / iOS 27.0 效果仍待用户关闭并重新打开确认。

## iPhone 顶部模糊兼容修复（2026-10-05）

截图中标题本身上缘变模糊，疑似主屏幕透明状态栏的系统叠层；页面顶部另外有 sticky 毛玻璃。主屏幕状态栏改为 `black`，让作品与文字显示在状态栏下方；窄于 900px 的媒体库及通用 sticky 页头使用不透明主题背景，关闭背景模糊和投影。底部玻璃胶囊和桌面页头效果保留。

主屏幕应用高度改为从根元素到应用容器的 `100%` 高度链，跟随实际布局视口，避免实色状态栏下 `100vh` 仍包含状态栏空间而裁掉底栏。普通浏览器仍使用 `100dvh`，键盘检测及关闭后恢复逻辑保持原有实现。

参考：[Apple 状态栏 meta 说明](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariHTMLRef/Articles/MetaTags.html)、[WebKit 实色状态栏的 vh 高度问题 #316008](https://bugs.webkit.org/show_bug.cgi?id=316008)。iOS 的启动状态栏设置可能随主屏幕入口保存：先完全关闭再打开；若顶部效果未变化，删除主屏幕旧图标，再从 Safari 重新添加 HE Manager。

生产构建和 46 项前端测试通过；Chromium 在 320×568、390×844、844×390、1440×900 下检查普通浏览器与模拟主屏幕模式：手机页头无背景模糊、底栏贴合视口、无横向溢出、sticky 滚动及图片详情打开/关闭正常。浏览器检查使用隔离 API/验收图，不修改生产媒体数据。服务器 WebKit 浏览器缺少 libwayland-server.so.0，未完成该引擎检查；系统状态栏与顶部模糊效果仍需 iPhone 真机复验。
