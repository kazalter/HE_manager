# HE 管家：项目读取能力与写入审批设计

日期：2026-10-10
状态：用户已批准设计和实施计划；已直接实施并发布。动态验证限制见发布记录。

## 1. 用户目标与范围

用户反馈管家能力受限，希望“可以读所有”，写入必须经本人批准，并提供审批 UI。范围经用户选择为整个 HE 项目：媒体库、媒体文件、目录、任务和运行日志。聊天方案已同意：全面读取，具体写入逐次审批，顶部待审批数量、右侧审批面板和聊天卡片。

成功标准：管家能回答 HE 中的资料、文件、运行状态问题；提出可执行的整理方案；用户能准确看到修改对象与前后差异，批准后观察真实执行结果。查询错误必须有可理解的原因。

默认隐藏密码、Token、私钥、登录凭据及含凭据的连接地址。包括备份在内的数据集通过业务查询和状态接口读取，不向模型开放数据库文件、凭据文件的原始字节。用户选择的是 HE 项目，不含其他 Linux 项目或系统管理。

## 2. 现状与选择

现有链路：网页 → HE 后端 → Hermes → MCP → assistant-tools。只有 7 个元数据查询工具和 2 个提案工具；提案支持评分、收藏、来源链接、标签、扫描。ProposalCard 已有预览、确认、拒绝及过期处理。后端具备身份验证、提案哈希、目标指纹、幂等执行和审计。

已观察到 MCP 将除暂时服务故障外的非 200 响应统一变成 he_tool_rejected。这能解释提示不具体，不能证明历史调用失败的根因；实施时需定位参数、身份、会话及业务错误。

考虑的实现方式：

1. 扩展已有结构化工具与审批后端（采用）：复用身份和审批，增加业务读取、受限文件读取、操作注册表；每种操作的预览与执行可核对。
2. 项目目录直接挂入 Agent，并依靠提示词限制写入：开发量较少，但不能保证所有写入都经过网页批准，不符合用户要求。
3. 把所有网页接口直接作为通用工具：覆盖快，但部分 GET 有副作用、返回凭据或大体积内容，不能保证读取语义和审批预览。

## 3. 读取能力

读取无需弹出审批，不修改业务数据，也不记录播放/阅读进度。查询保留用户、会话和运行绑定验证。

| 领域 | 提供内容 |
| --- | --- |
| 媒体资料 | 全部媒体类型、缺失与重复状态、标题、作者、标签、评分、收藏、进度、来源及所在根目录编号；支持筛选、排序、分页与统计。服务器绝对路径与相对路径不发给模型（2026-10-11 修订，见发布记录） |
| 标签与作者 | 名称、关系、数量、作者关联媒体及重复标签信息 |
| 目录与文件 | 已登记媒体根目录及子目录；列表、类型、大小、修改时间、文件存在性、媒体对应关系 |
| 媒体内容 | 有界文本读取；图片、漫画页、封面预览；音视频文件信息和可播放预览链接 |
| 任务与日志 | 扫描、下载/导入、自动同步及管家任务状态；已有业务日志和新增脱敏运行日志 |
| 系统状态 | HE 健康、磁盘空间、挂载状态、备份数量与时间、非敏感有效设置 |

工具按领域拆分，参数和返回使用严格 DTO，工具注册表、MCP schema、提示词、返回验证同步更新。不得通过 SQL、命令或任意 URL 参数变成通用执行器。

每次列表最多 50 项，文本最多 32 KiB，日志最多 200 条；超出提供游标和截断说明，不默默只返回部分。媒体文件列表、文本、预览通过逻辑根目录 ID 与相对路径定位。现有普通媒体查询默认保持正常库视图，但新状态过滤支持查询缺失、重复、待检查记录，统计说明过滤条件。

文件读取验证真实路径属于服务器配置的 HE 根目录；目录中的符号链接、压缩包路径、绝对路径与父目录跳转不得逃出根目录。文本识别和压缩包读取有大小/条目上限。预览使用当前登录用户授权或短时用户绑定链接；URL 不附带账号凭据。

预览能在网页查看不等于模型已经分析内容。MCP 返回受支持的图片内容块时，只有已确认支持图像输入的模型才可分析；否则返回文件信息和预览卡片，明确“未分析文件内容”。本次不引入 OCR、语音转写或视频逐帧分析服务。

运行日志使用脱敏后的结构化事件，含时间、服务、级别、事件码、业务对象和摘要。禁止把原始请求体、环境变量、提供商配置、认证头或完整 traceback 作为日志工具输出。通过应用日志收集器写入有轮转和保留上限的 HE 日志目录；不挂载 Docker socket。备份工具读取备份清单与新鲜度，不读取备份内账号表。

## 4. 写入能力与操作注册表

全部业务写入只能生成提案；Agent 的工具身份不能调用确认接口。HE 管家网页当前登录管理员执行确认。新增写入范围为：

- 媒体资料：保留现有字段，增加标题、作者、阅读/观看状态；单项或明确列出的批量变更。
- 标签整理：改名、合并，展示涉及的标签与媒体清单。
- 任务：扫描目录、复查缺失/重复状态、重建缩略图、创建数据库备份（本次不自动清理旧备份）。
- 文件：改名、移动单个媒体文件或单个漫画目录，并同步该媒体与其明确列出的关联路径。

本次不增加永久删除文件、目录整树重组、任意脚本/终端、代码部署或凭据修改。文件改名和移动属于用户同意的“文件整理”，其他操作后续可继续加入同一审批注册表。

每种操作定义参数 schema、显示名称、权限、预览、目标指纹、执行器和结果 DTO。拒绝未注册的操作。共用业务服务，避免把有副作用的公开路由直接当成读取工具调用。

提案保存不可变规范化 payload、目标集合、目标指纹、前后数据、操作原因、影响数量、是否可撤回与失效时间。沿用当前提案有效期；网页显示准确时间。批量上限 50 个明确对象；批量每个对象的结果独立可查，整体事务结果也必须明确；审批前可选择对象，选择变化必须由服务器生成新的提案和哈希，不能由前端修改已批准的 payload。批量资料变更采用单事务；文件提案一次只处理一个媒体对象，不提供混合操作的原子承诺。

## 5. 审批与执行

流程：提出操作 → 后端构建预览 → 显示待审批 → 用户批准/拒绝 → 后端重新验证 → 执行或排队 → 返回真实结果与审计。

确认必须验证当前管理员、提案所属用户/会话、原运行仍可用于审批、未过期、payload 哈希和目标指纹。沿用现有停止/失效运行的提案不可确认规则。目标、关联关系、源文件或目标目录变化后，提案标记失效，重新生成后再审批。批准只授权卡片列出的操作，不形成永久写权限。

重复点击或断线重试不得重复操作；同提案返回同一执行结果/任务 ID。状态区分待审批、已拒绝、已过期、资料已变化、排队中、执行中、成功、失败与需要恢复。确认后的任务独立于聊天，停止聊天不等于取消任务。

文件操作由后端执行，Agent 和 assistant-tools 的媒体挂载只读。只允许已登记 HE 媒体根目录之间的同文件系统移动；拒绝覆盖已有文件、跨盘移动、根目录改名、越界与符号链接路径。审批明确显示源路径、目标路径、受影响数据库字段和关联对象。

文件系统与 SQLite 不能视为同一原子事务。执行器使用持久操作日志、源文件身份/大小/时间指纹、目标预检查与扫描/写入协调锁；先记录意图，再移动，再更新所有受影响路径，最后记录完成。失败尽量恢复源路径；启动时检查未完成操作，状态不明时标记“需要恢复”，禁止自动重放和后续冲突操作。源/目标重新验证在锁内进行。覆盖、硬链接、跨盘复制删除均不属于本次文件执行策略。

数据库类批量修改在事务内重新验证全体目标，失败不提交。长任务使用既有任务机制或专用持久任务执行器，展示进度和结果；取消只在执行器支持并能确认停止的阶段提供。撤回操作只在可验证的情况下提供，撤回也创建新提案并再次审批。

## 6. 审批 UI

沿用现有主题和左侧对话历史布局：

- 对话顶部增加“待审批 · N”，统计当前用户全部有效待审批提案；聊天卡片保持上下文。
- 桌面点击打开右侧审批面板；手机使用带遮罩、独立滚动的抽屉。
- 面板分为“待审批 / 执行记录”，标明所属对话，支持跳转；分页加载。
- 卡片显示操作类型、原因、对象、影响数量、前后差异和失效时间；批量可展开清单，文件显示完整路径。
- 使用明确按钮文字：批准修改、批准移动、批准启动任务、拒绝。确认过程中禁用重复点击。
- 执行记录显示排队/进行中/完成/失败、时间和结果，失败提供可理解的原因及下一步。
- 顶部提供只读能力说明：“可读取 HE 项目；修改需你批准”，展开显示实际可用能力，不暴露内部 Token 或数据库结构。
- Esc 关闭面板，焦点限制在打开的抽屉内，关闭后归还触发按钮；按钮触控区域不少于 44px，长路径换行，320px 起无横向溢出。

审批列表需要用户级查询接口；维持会话级接口兼容。审批记录来自后端，不信任模型生成的“已执行”文字。聊天卡与面板同步状态。

## 7. 错误、部署与兼容

MCP 对已知安全错误码做白名单映射：参数错误、会话不可用、未授权、资料不存在、超出读取范围、内容过大、资料已变化、服务暂不可用。错误 DTO 带可追踪 ID；服务端记录脱敏错误码，不把内部 HTTP 响应全文传给模型。

现有 9 个工具和已保存提案继续可用。数据库用幂等迁移扩展提案、任务与文件操作日志，默认值兼容旧数据。Hermes 依旧只挂自身运行目录，通过受控工具读取 HE。

部署通过 Linux SSH 在 /opt/stacks/he-manager 构建。读取工具仅增加所需媒体/日志只读挂载；保留现有凭据遮罩，备份清单由后端提供。后端、MCP schemas、Hermes 工具配置与前端作为同一版本发布。停启前确认无活动运行/文件任务，先备份数据库和现有镜像；前端先构建到 staging 后发布，保留旧哈希资源。

## 8. 验证标准

必要检查用例：所有读取无业务写入；用户隔离和失效运行；正常/缺失/重复筛选；文件越界、符号链接、超大内容与压缩包路径；凭据不进入日志/结果；参数错误提示；任何未批准操作不能修改；提案篡改/过期/目标变更/重复确认；批量回滚；文件执行各阶段失败及启动恢复；聊天/面板状态同步；桌面与手机审批、键盘焦点；前端生产构建与部署健康。

验收示例：询问缺失文件与扫描失败原因；查看漫画目录和页面预览；提出 3 项标签整理并拒绝其中一项；批准单个媒体改名，确认磁盘和库路径一致；刷新页面后可查询审批和执行记录。
