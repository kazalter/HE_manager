# HE Manager Windows 原生客户端实施计划

日期：2026-10-17。状态：计划已制定，尚未开始原生客户端实现。

## 目标与优先级

当前主目标是 Windows 原生客户端。暂停扩展 Electron 客户端，Mac 原生版后置；保留已交付体验包，不删除现有源码。项目仍只有一个仓库、一条 main，服务器继续使用现有 FastAPI 服务。

首版必须能直接代替现有桌面壳完成本地库的浏览、视频播放、图片／漫画阅读和本机 GPU 超分。视频必须在主窗口内播放，进入全屏后沿用同一播放会话；不能通过启动独立 mpv.exe 窗口来完成验收。

本轮仅制定计划和核实接口，不安装开发工具、不创建空工程、不修改现有服务部署。

## 已核实的基础

- Windows 11 家庭版 x64，Build 26200；目标 GPU 为 RTX 5070 Laptop。已有 Windows 包的原生自检观察到 NVDEC 和真正的 Anime4K 渲染通道。
- 已有通用图片 4× 和动漫 2× 原生推理引擎、模型、着色器与校验清单，可复用经过验证的资源；不移植 Electron 的 IPC 或浏览器代码。
- Windows 的 dotnet 命令可用，但本轮 `dotnet --list-sdks` 未列出 SDK。实际 .NET SDK、Windows SDK、MSVC 和 WinUI 构建环境须在 WN-01 中核实和准备。
- API 的服务器地址、登录、媒体分页、Range 读取、漫画页、收藏、评分、进度均已在仓库核对。首版不需要新后端或数据库迁移。

## 技术方案

| 部分 | 选择与作用 |
| --- | --- |
| 原生界面 | C# + WinUI 3 / Windows App SDK；XAML 原生控件，保留 HE 的媒体卡片、亮暗主题与阅读布局 |
| 应用运行时 | .NET 10 LTS；具体补丁、Windows App SDK、NuGet 与构建工具在 WN-01 验证后锁定，不使用浮动版本 |
| 播放器 | 进程内 libmpv 的 C API；统一封装播放状态、命令、事件与销毁，不再依赖独立播放器 JSON IPC |
| 视频显示 | 优先验证 libmpv D3D11 Render API → DXGI swap chain → WinUI SwapChainPanel；用薄 C++ 互操作层隔离图形指针、线程与资源释放 |
| 视频超分 | 已验证的 Anime4K 原画／效率／质量配置；优先验证同设备 D3D11 硬件解码，按兼容性比较其他解码路径，不承诺固定使用 NVDEC |
| 图片超分 | 复用 Real-ESRGAN NCNN/Vulkan 引擎；独立后台任务、可取消、单 GPU 作业，输出交给原生图片控件 |
| 服务连接 | HttpClient 调用 HE API；登录凭证使用 Windows 当前用户保护的存储；换服务器隔离账号与缓存 |
| 分发 | Windows x64 自包含体验包，封装 .NET、Windows App SDK 和所需原生资源；不让用户安装 CUDA、Node 或 Python。安装程序放在 WN-07 验证 |

WinUI 3 是微软面向新 Windows 桌面应用推荐的原生 UI 框架。libmpv 上游目前提供 D3D11 render 接口，支持把帧渲染到调用方创建的纹理；WinUI 提供 SwapChainPanel 的原生 swap chain 接口。但这不等于我们现有 mpv.exe 包已带有对应的 libmpv DLL、匹配 ABI 或完整工作链路，必须先做 WN-01 原型验证。

不从零实现解码器、GPU 推理框架和模型。既有后端及经过验证的模型资源复用；Windows 的页面、窗口、输入、全屏与渲染生命周期重新实现。

## 第一关：先验证播放器渲染，后铺开界面

以下任何一项未通过，不开始批量编写媒体库页面：

1. 原生主窗口内呈现合成测试片，能显示真正的视频帧；没有独立播放器顶层窗口。
2. 硬件解码可识别；Anime4K 开／关及两档切换确实改变渲染配置，有渲染通道证据，不只改变按钮文字。
3. 控制条能叠在视频上并正确接收输入；窗口缩放、最小化恢复、焦点切换、DPI 改变后仍能显示。
4. 在同一播放会话中进入／退出全屏，进度和解码器不重建；全屏放在当前显示器，退出恢复原窗口位置和尺寸。
5. 切换视频、关闭页面、退出应用后停止解码和 GPU 作业；不遗留窗口、线程或持续增长的显存。
6. 固定一个支持所选 render API 的 libmpv 构建，记录来源、版本、ABI、SHA-256 和所需依赖。

现有发行包若不支持 D3D11 render 接口，先更换或构建匹配 DLL。仍失败时记录兼容证据、比较可嵌入的 OpenGL render 路径并重新估算；不悄悄回退到另起窗口。普通 HWND 子窗口嵌入只能作为研究对照，不能把控件遮挡／焦点问题留到最后。

## 首版功能范围

- **账号与连接**：服务器连接测试、现有账号登录、过期提示、退出、服务器切换。
- **媒体库**：分页媒体卡片、视频／漫画／图片／音频分类、搜索、排序、收藏和标签筛选、继续观看、详情、收藏与评分。
- **视频**：主窗口播放、播放／暂停、音量／静音、拖动进度、上一项／下一项、字幕与音轨选择、倍速、恢复播放位置、全屏、Anime4K 档位和解码／掉帧信息。
- **图片与漫画**：单页、双页、卷轴、RTL、缩放和平移、快捷键、全屏、预加载与失败重试；动漫 2×、通用图片 4×，任务失败或取消时继续显示原图。
- **音频**：通过同一媒体引擎播放、暂停、跳转和音量；媒体浏览时保留播放条。首版不承诺复刻现有全部 ASMR 字幕能力。
- **应用设置**：浅色／深色／跟随系统，服务器和账号、默认超分档位、GPU 信息、缓存大小与清理、窗口位置记忆。

首版媒体超分保证静态 JPG／PNG；其他常用格式按原生解码能力逐项验证并列出结果，不把静态图片模型用于动画帧或承诺所有视频格式。普通真人视频提供原画播放；专用普通视频 AI 超分另行评估。

首版后再接入 Pawchive／X／WNACG／ASMR 外部源浏览与下载、AI 管家、统计／去重／用户管理、批量维护、离线下载、自动更新、完整 HDR 映射与色彩管理。缺少的功能不放空白入口，也不通过嵌入网页充数。

## 接口契约与复用边界

| 业务 | 现有接口与约定 |
| --- | --- |
| 连接与账号 | GET /auth/status；POST /auth/login；GET /auth/me；POST /auth/logout |
| 媒体分页 | GET /media；limit、offset、media_type、search、favorite、tag、source_site、view_status、sort；从 X-Total-Count 读取筛选后的总量，不能一次拉全库 |
| 详情 | GET /media/{id}；该接口会更新 last_opened_at/view_status，只在真正打开媒体时调用，不用于封面预加载 |
| 媒体流 | GET /stream/{id}，使用 Authorization 头；保留 Range/206、416 与取消语义，鉴权不能进入进程参数或日志 |
| 漫画页数 | GET /manga/{id}/pages?include_dimensions=true；沿用服务器页面排序及尺寸 |
| 漫画图片 | GET /manga/{id}/page/{page_index}；page_index 从 0 开始；预加载不设置 track_progress=true |
| 收藏／评分／进度 | PATCH /media/{id}；favorite 布尔、rating 0～5；视频 progress 是整数秒、漫画 progress 是从 0 开始的页码 |
| 标签 | GET /tags；首版读取和筛选，不增加独立的标签数据库 |
| 封面 | 使用现有 cover_path 对应的 /thumbnails 路径，不把服务器绝对路径当成本机文件路径 |

写入字段保持当前服务器语义，不引入新的“每个用户私有进度”假设。播放每约 5 秒节流保存，暂停／正常退出补交最终位置；发送串行化，避免旧请求覆盖新位置。切页后丢弃旧画面回调，账号／服务器切换时取消旧任务和待发送更新。

## 图片超分任务设计

- UI 区分排队、处理中、成功、取消、超时、格式／尺寸不适用；处理期间可翻页，原图一直可用。
- 当前页／跨页优先；翻走的排队任务取消，正在运行但已无订阅者的作业可终止。使用有上限队列，不因连续翻页无限积压。
- 同一图／账号／模型共用任务；区分调用方取消和应用关闭，取消一次任务不会永久关闭整个服务。
- 保留已验证的 tile 256 和像素预算作为起点；对 5070 Laptop 实测后再调整，不把所有机器硬编码成 NVIDIA 专有路径。
- 4× 是宽高各四倍、像素十六倍；预估尺寸、磁盘和内存后决定是否运行，超限说明原因并保留原图。
- 缓存隔离服务器、用户、内容与模型版本，默认约 1GB；结果原子写入，错误／关闭时清理临时文件，提供清理入口。
- 缓存命中仍验证读取权限，权限失效或换账号不复用另一账号的结果；不能绕过服务器授权。

## 真机验收矩阵

- 视频：H.264／HEVC／AV1 的 MP4／MKV 代表样本，1080p24／1080p60／4K24 分开记录；字幕、音轨、倍速和 HTTP 拖动；Anime4K 原画／效率／质量单独记录。不可用的组合明确列出。
- 30 分钟播放去掉起播／跳转阶段后，掉帧比例目标低于 0.1%；达不到则调查或降低默认档位。记录渲染器、实际解码方式、源／输出尺寸、GPU 占用／显存、CPU、帧时间；功耗／温度仅在设备提供可靠传感器时记录。
- 图片：小图、约 1000×1400 图、长图、超限图，2×／4× 输出尺寸与显示比例；翻页期间取消、损坏图、未知格式、磁盘不足、退出重开与缓存命中。
- 窗口：全屏／还原 20 次、切片 50 次、快速翻页与切档 50 次；前后记录进程、句柄、内存和显存，检查是否持续增长。
- 网络与账号：断网、401、服务重启、慢流、Range/416、切换服务器／账号；不会把上一视频的进度写到下一视频，也不显示上一账号缓存。
- UI：100%／150%／200% DPI、窗口最小尺寸、不同分辨率显示器、Alt+Tab、系统亮暗切换；全屏退出恢复原有窗口，Esc 首次退出全屏、再次关闭查看器。
- 资源：启动／退出无需残留 mpv.exe 或推理子进程；后台作业能取消；下载模型和动态库采用固定版本与哈希。

上述数值是待验收目标，不是已测得的性能。合成片可证明链路工作，不能替代用户日常内容的长时播放与观感检查。

## 代码组织与构建

拟在同一仓库增加 windows-native/：

- HEManager.Windows：WinUI 页面、视图模型、窗口与输入。
- HEManager.Core：API、媒体模型、分页、凭证接口、观看会话与超分任务策略。
- HEManager.Media：libmpv 生命周期、播放命令、事件、状态与硬件能力。
- HEManager.Graphics：薄 C++／D3D11／SwapChainPanel 互操作层，不放业务代码。
- HEManager.Tests：契约、任务取消／缓存、进度顺序和生命周期测试。
- scripts、resources、runtime-lock：可重建构件、原生资源来源、锁定版本与校验。

源代码仍在 Linux /opt/stacks/he-manager 维护。WinUI、XAML 和 C++／Windows SDK 产物需要 Windows 工具链；计划在用户 Windows 的隔离构建目录或 Windows CI runner 完成编译和 GUI／GPU 验证，不把 Linux 上生成文件当作 Windows 运行验收。Windows 工作副本只用于构建与验证，生成内容不覆盖 main 源码；相关 SDK／Build Tools 的安装在 WN-01 单独记录。本轮尚未执行这些安装和编译。

先确认仓库的 Windows 构建入口、工具版本和可用空间，才确定具体构建目录。CI 先做可执行构建和核心测试；GPU 与全屏只能由真机交互测试确认。发布保留依赖许可、来源、版本和校验信息；开发者签名和自动更新安排在正式分发阶段。

## 执行规则

1. 遵循根目录 AGENTS.md：单一 main、分阶段提交、每阶段验收后更新主计划。
2. 先完成 WN-01，不同时搭建另一套 Mac 原生 UI，也不继续扩大 Electron 功能。
3. 每阶段交付可验证结果：原型、界面或安装包及证据；构建通过、测试通过、实机体验通过分别记录。
4. 现有生产服务、数据库和媒体原文件保持现状；需要接口增补时先记录契约差异，另行完成兼容改动。
