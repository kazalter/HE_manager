# 删除并丢弃（2026-10-12）

## 使用

- 管理员可在媒体库卡片、媒体详情、WNACG 收藏卡片和 X 的“收藏与导入记录”中选择“删除并丢弃”。
- 桌面媒体库与 WNACG 卡片上的删除入口仅在鼠标移入或键盘聚焦时显示；移出并离开焦点后隐藏，不拦截封面点击。触屏设备保留可见入口。
- 预览列出文件/目录、附件范围、媒体数量与实际大小；勾选确认后才能执行。X 单张媒体只处理该附件；X 整帖操作处理该帖各导入来源的本地附件。
- 删除本地媒体文件并移除普通 Media 行，持久保存丢弃来源身份、原路径、时间和清理结果。不会取消网站收藏。
- `/discarded`（桌面侧栏／手机“更多”）可搜索、分页查看丢弃记录。未完成文件清理提供“重试清理”；完成后可显式“允许重新下载”。后者不会恢复已删除文件。
- 原先 `DELETE /media/{id}` 的索引移除接口仍保留兼容语义；网页原缺失文件移除入口已改为新确认流程。重复管理的确认删除文件也记录丢弃身份。

## 来源与扫描

- 新建 `discarded_content` 和 `discarded_identities`，沿用幂等迁移，不改旧表列或既有数据。
- 目录路径以规范绝对路径摘要识别；WNACG/ASMR 按站点条目 ID；X 按 tweet ID + 附件索引／整帖标识；Pawchive 按来源附件身份。
- 丢弃身份独立于媒体行、下载目录、标题和账号来源，因此重扫、重复导入和来源标题变化不会清除它。
- WNACG 自动下载筛选、手动计划/下载/入库、外部下载中心推送及回调均检查丢弃身份。X 发现、待导入筛选和逐附件导入均保留/检查丢弃状态。Pawchive 下载也拒绝已丢弃附件。
- 本地扫描跳过保留的丢弃路径，并识别 `source.txt`、`tracks.json` 和 X `info.json` 中的来源身份，阻止移动后重新入库。
- WNACG 收藏列表将丢弃状态合并到已有 SQL 查询中，分页读取保持至多三次查询，无 GET 写入。

## 删除与失败

- API 必须当前管理员、明确 `confirm=true` 与预览摘要。重新计算来源、关系、路径及文件/目录清单摘要；确认前变化返回 409。
- 复用项目独占文件操作锁，扫描/下载/其他媒体变更运行时拒绝删除。拒绝媒体根目录、范围外路径、符号链接路径、未挂载存储与未选择的嵌套媒体条目。
- 目录预览最多 100000 项。目录树变化使确认失效；常规文件只删除被确认的该文件，不自动删除相邻字幕等其他文件。
- 先事务提交丢弃身份、外部引用状态与 Media 移除，再清理字节。文件清理失败或中断仍保持下载阻止，状态可查看；启动仅恢复已提交的待清理操作。对原路径被替换的新文件拒绝清理。
- X 整帖保留 `info.json` 等来源元数据，只删除被列出的媒体文件；媒体库丢弃记录是后续跳过的持久依据。
- 第三方下载器已经收到的任务不由本项目取消。其完成回调不能重新入库已丢弃内容，扫描也会跳过已记录路径。
- 本地文件是永久删除；仅恢复数据库不能恢复文件。当前用户未授权删除某条真实媒体，线上检查只打开预览并取消。
